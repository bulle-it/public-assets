# Build & update — "Design of 00 and the projects" visuals

The 7 SVGs in this folder are generated by `gen.py`, one per top-level branch of the
Xmind map. Do not hand-edit the `.svg` files — edit `gen.py` and regenerate.

Palette and primitives are NOT defined here: they live in `../../lib/flatvec.py`,
shared with every other image set in this repo. Change a colour there and every set
follows; add a builder used by only one set (`f_copy`, `f_hub`… here) in that set's
own `gen.py`.

## Regenerate

```
python3 gen.py
```

Writes all `*.svg` next to the script and rewrites `INDEX.md` (Xmind node id -> file).
Output is deterministic; a clean run produces no diff unless `gen.py` or `flatvec.py` changed.

## Change one image

1. Find its `add(<anchor>, "<name>", <builder>(...))` line in `gen.py`.
   `<anchor>` is the Xmind topic id (see `INDEX.md`).
2. Edit the builder above it.
3. `python3 gen.py`
4. Push (Contents API or git — no clone is required, see the repo README).
5. Re-attach the changed node(s) in Xmind (MCP `xmind_set_topic_image`):
   - fileId `AP0rhLDy`
   - topicId = the anchor
   - imageUrl = `https://raw.githubusercontent.com/bulle-it/public-assets/main/maps/Projects_Architecture/<file>?v=N`
   Bump `N` whenever the file name is unchanged but the content changed, so Xmind
   treats it as a new URL and re-fetches (raw.githubusercontent.com ignores the
   query string). Confirm with `xmind_get_topic`: `imageSource` hash must change.

Note: every SVG carries `width`/`height` (viewBox x2). Without an intrinsic size
Xmind pins the image small and double-click zoom does nothing.
